# 二维码卡片：产品定位与首版验收

- 决策日期：2026-10-29（Asia/Shanghai）
- 状态：首版和后续扫码、导入、打印改进已实现；最新验证见文末 2026-11-05 记录。真实用户验证与纸质打印验证待进行。
- 证据边界：竞品能力来自下列官方页面；用户需求、完成时长和市场接受度尚未经过实测。

## 目标用户与任务

第一批面向使用 Android 手机的小店主、摊主和小型活动组织者。他们需要把一段内容放到桌牌、海报、名片或聊天图片上，让别人扫码完成一个明确动作。

优先解决三件事：

1. 把现有 Wi-Fi 的连接信息分享给客人。
2. 把已有的菜单、报名表、作品或店铺页面链接分享出去。
3. 把姓名和联系方式分享给别人。

这里的「菜单」指用户已经拥有的页面网址。本产品不创建菜单网页，不提供在线点餐，也不托管用户文件。内容在本机生成；访客打开网址仍可能需要联网。

## 定位与产品承诺

**在手机上填好内容，就得到别人看得懂、可以直接分享的二维码卡片。**

差异化来自「按用途开始 → 填必要内容 → 自动排好卡片 → 本机识别检查 → 分享或保存」的完整流程。用户不必先理解编码类型，也不必进入通用设计编辑器排版。

首版对外表达建议：

- 主文案：把内容做成一张能用的二维码卡片。
- 用途说明：连 Wi-Fi、留联系方式、分享页面，填好就能发。
- 信任说明：内容在本机生成。

免费、离线、Logo、美化和不限制扫码次数均已有竞品提供，不作为独家能力宣传。二维码卡片也已有通用设计工具支持；我们的假设是聚焦用途、自动排版和本机检查能减少完成任务的步骤。

## 已决策的首版范围

### 按用途制作

- 显眼入口聚焦 Wi-Fi、已有页面链接、联系方式。
- 用途名称以用户动作表达，不要求首次使用者理解 vCard 等术语。
- 现有其他类型保留在更多类型入口，高级样式保留在调整样式入口。
- 示例只作为提示或明确的演示内容，不将示例误当作用户正式数据。

### 成品卡片

- 自动组合用途标题、二维码和简短说明。
- 用户能预览最终保存的卡片内容，并选择需要的输出形式。
- 保留纯二维码能力，照顾已有用户。
- Wi-Fi 卡片默认不把密码排成可见文字；这不意味着二维码内的凭据被加密。
- 卡片排版保持二维码周围留白；装饰不覆盖可扫码区域。

### 本机识别检查

- 对生成结果执行本机解码，并比对解码内容与预期内容。
- 只在实际完成检查后展示通过状态；内容、样式或导出尺寸改变后，旧检查结果不能继续代表新结果。
- 通过文案限定为当前图像的识别结果，例如「已识别，内容一致」。
- 未通过时给出可执行建议，例如减少 Logo 遮挡、使用深色码点与浅色背景、恢复基础样式。
- 本机检查不验证网址可访问、Wi-Fi 凭据正确或联系人信息真实，也不保证所有手机和打印环境可扫。

### 保存与复用

- 支持分享或保存成品，文案准确对应实际输出。
- 保留本地历史复用，展示易读的用途和摘要。
- 历史列表不直接展示 Wi-Fi 密码；读取与导出二维码仍能得到码内凭据。
- 权限被拒、没有分享应用或取消文件选择时，有明确可恢复路径。

## 首版明确不做

- 动态短链、远程修改已经印出的二维码内容。
- 扫描统计、账号体系、云同步和多人管理。
- 菜单网页、在线点餐、文件或媒体托管。
- AI 艺术二维码、模板商城和复杂批量任务。
- 对任意设备、光照、材质或印刷尺寸作百分之百可扫描承诺。

这些取舍用于验证当前定位，不代表永久排除后续能力。

## 必须准确表达的边界

| 场景 | 应表达 | 避免表达 |
| --- | --- | --- |
| 菜单或活动 | 粘贴已有菜单或报名页面网址 | 创建菜单、自动搭建报名页面 |
| Wi-Fi | 把网络名和密码写入二维码，持有码者可以读取或使用 | 密码已加密、隐藏密码所以无法读取 |
| 离线 | 制作二维码不需要上传内容 | 打开任意网址无需联网 |
| 检查通过 | 当前生成图像能被本机识别，内容一致；使用前仍可用实际设备试扫 | 所有手机都能扫、打印保证可用 |
| 静态二维码 | 内容写入图案；网址或凭据变化后需要更新二维码 | 链接永久有效、以后可远程修改 |
| 联系方式 | 扫码查看或导入联系人，具体行为取决于扫码应用 | 一扫自动加好友、保证自动保存联系人 |

## 待验证假设

1. 目标用户需要带用途说明的成品，而不只是二维码图片。
2. 三个主要任务覆盖第一批目标用户的高频需求。
3. 用户能在不进入高级样式页的情况下完成首次制作。
4. 本机检查能提升使用信心，且用户理解它不保证真实印刷效果。
5. 用户愿意安装 Android 应用完成任务，而不是继续使用网页或微信生态现有工具。
6. 用户愿意复用历史卡片，手机端的本地保存比一次性网页制作更有价值。

目前没有用户访谈、转化率、留存率或付费意愿数据支持以上假设。

## 5–8 人实测方案

招募 5–8 名实际使用 Android 的潜在用户，覆盖小店或摊位经营者、活动组织者；优先纳入过去一个月有过制作二维码经历的人。参与者自愿提供或使用测试网络及测试联系方式，避免要求公开个人凭据。

每人安排约 20–30 分钟，使用可安装的测试版本。主持人只给任务，不先演示入口；用户受阻时先记录原因，再提供帮助，并将该次任务记为需要协助。

1. **Wi-Fi 任务**：使用测试网络信息，为到访客人制作一张可分享的卡片。
2. **链接任务**：给出一条现有的菜单或活动页面网址，制作能让访客理解用途的卡片。
3. **联系人任务**：使用测试姓名与电话号码制作联系卡。
4. **交付理解**：让另一位参与者只看成品，描述扫码后预期发生的动作，再实际扫码。
5. **检查理解**：询问「识别检查通过能说明什么？打印以后还需要什么验证？」
6. **复用任务**：从历史找到刚才的内容并再次使用，观察是否误操作、是否泄露不希望展示的信息。
7. **替代选择访谈**：了解原有工具、安装意愿、使用频率和仍需补足的能力，记录原话，不以赞同反馈替代真实行为。

至少记录：任务完成情况、需要帮助的节点、从启动到首次成功导出的时间、是否进入高级设置、选错类型次数、失败恢复情况、成品用途理解和检查含义理解。

### 成功指标：以下均为目标，不是已取得的数据

| 指标 | 首轮目标 | 判定方式 |
| --- | --- | --- |
| 首次成功导出 | 中位时长不超过 60 秒 | 从进入首页到成功保存或唤起有效分享记录时长；同时报告所有参与者结果 |
| 无协助完成 | 至少 80% 的任务无需主持人提示完成 | 以任务为单位计数，保留失败原因；小样本不外推为市场转化率 |
| 主路径简洁 | 至少 80% 的参与者首次完成无需进入高级样式 | 观察操作路径 |
| 成品可理解 | 至少 80% 的观察者在扫码前能说出正确用途 | 展示成品后提问，避免暗示答案 |
| 检查含义 | 所有人都能区分本机识别与真实打印保证 | 发现误解即调整文案；这是理解目标，不是扫描成功率 |
| 基础扫码 | 每种主要内容至少在两种独立扫码实现上完成预期识别 | 分开记录屏幕图像和纸质打印结果、设备与测试条件 |
| 信息边界 | 不出现把 Wi-Fi 码理解为加密保密、把菜单入口理解为托管建站的情形 | 任务后复述与观察；发现一例即回查提示与名称 |

样本量用于发现可用性问题，不能证明市场规模、留存或商业可行性。指标未达标时优先修改入口、字段和默认输出，不先增加新功能。

## 扫码与制作流程更新（2026-11-05）

- 首页以「连 Wi-Fi／分享页面／留联系方式」开始；相机与图片导入并列，窄屏或大字号时纵向排列。恢复已有草稿直接进入编辑。
- WeChatQRCode 2.4.0 仅打包 ARMv7、ARM64，统一 `QrScanner`、`QrScanContract` 供其他页面复用；照片入口不申请相机权限。
